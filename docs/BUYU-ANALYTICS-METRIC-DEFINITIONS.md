# Buy-U Analytics Metric Definitions

All metrics use exact integer sen for monetary calculations, Malaysian timezone (`Asia/Kuala_Lumpur`, UTC+8) for date windows (`7d`, `30d`, `90d`, `this_month`, `all`, `custom` inclusive full MYT days), paginated full-table loading (`fetchAllPaginated` in 1,000-row chunks with deterministic ordering — including composite `(viewed_at, viewer_id, listing_id)` on `listing_views` which has no `id` column — so Supabase row limits never silently truncate totals), and authoritative payment verification (`isAuthoritativeOrderPaymentVerified`). All equations below were independently reconciled against live hosted PostgreSQL rows in Gate B (`B5/B6/B7`) and live UI/CSV exports in Gate C (`J/K/L`). No historical events are fabricated prior to activation.

| Metric | Source Tables | Calculation | Inclusion / Exclusion | Denominator / Edge Case | Role Access |
| --- | --- | --- | --- | --- | --- |
| **Verified Unified Checkouts vs Child Orders** | `orders`, `checkout_sessions`, `payments` | `verifiedCheckouts`: distinct `cs:<checkout_session_id>` (counted once across multi-seller unified checkouts) + distinct `ord:<order_id>` (for legacy standalone orders). `verifiedTransactions`: total verified child orders (`periodOrders.length`). | Excludes unpaid, pending_payment, expired, and cancelled orders; never double-counts parent checkout sessions with child orders | `0` if no verified paid orders in window | Admin (all) |
| **Gross Verified Product Sales** | `orders`, `checkout_sessions`, `payments` | `SUM(orders.subtotal_sen)` | Verified paid orders only; excludes unpaid/expired/cancelled, ToyyibPay RM 1.00 FPX fees, off-platform services, and free donations | N/A | Seller (own), Admin (all) |
| **Net Product Sales** | `orders`, `order_refunds` | `Gross Verified Sales - SUM(succeeded refund_amount_sen)` | Deducts executed (`succeeded`) simulated refunds only | N/A | Seller (own), Admin (all) |
| **Category / Product Net Sales (Proportional Estimate)** | `orders`, `order_items`, `order_refunds` | Exact integer-sen largest-remainder distribution (`allocateProportionalSen`) of `netOrderSen` across item gross line totals | Explicitly labeled proportional order-level refund estimates; item allocations sum identically to order-level net totals with zero rounding drift (verified live on 500 sen refund split `333 + 167 = 500`) | Returns `0` if `orderItemsGrossSum === 0` | Seller (own), Admin (all) |
| **Net Platform Commission (2%)** | `orders`, `order_refunds` | `SUM(commission_sen) - SUM(succeeded commission_reversal_sen)` | Excludes ToyyibPay RM 1.00 FPX fee (not platform profit) | N/A | Seller (own), Admin (all) |
| **Net Seller Earnings (Pre-Expense)** | `orders`, `order_refunds` | `SUM(seller_net_sen) - SUM(succeeded seller_deduction_sen)` | Explicitly labeled pre-expense (never called "profit") | N/A | Seller (own), Admin (all) |
| **Period Growth %** | Selected window vs equal-length prior window | `((current - previous) / previous) * 100` | MYT window boundaries (`7d`, `30d`, `90d`, `this_month`, `custom`) | Returns `null` (`N/A`) when `previous === 0` or `range === 'all'` | Seller, Admin |
| **Measured Active Users & Daily Trend** | `orders`, `listing_views`, `service_requests`, `free_notice_claims`, `profiles.last_active_at` | Period total = distinct user IDs across dated events + `last_active_at`; daily trend reconstructed strictly from dated events (`paid_at`, `viewed_at`, `created_at`) | NEVER counts dormant accounts merely because `profiles.status = 'active'` | Tracking of `listing_views` & `last_active_at` begins at Phase 8F activation | Admin only |
| **Listing Views & Attributed Conversion %** | `listing_views`, `orders`, `order_items` | Daily deduplicated `(viewer_id, listing_id, view_day)` excluding seller self-views; `attributablePurchasers / uniqueViewers * 100` where purchaser has a qualifying view `<= orderTs` in window (subset guarantee — NO clamping); `ordersPerViewer` shown separately | Published listings only; unattributable purchases (no qualifying pre-purchase view) yield `N/A` for conversion while preserving `ordersPerViewer` | Returns `null` (`N/A`) when `uniqueViewers === 0` or purchases lack pre-purchase view attribution | Seller (own), Admin (all) |
| **Student Business Sellers** | `listings`, `orders`, `order_items` | Strictly `listings.kind = 'business'` (food businesses store `kind = 'business'` with `is_food = true`; never classifies non-business listings by `is_food`) | Separated from `pre_loved` sellers, `service` providers, and `free_notices` donors; multi-item orders attributed proportionally via `allocateProportionalSen` | N/A | Admin only |
| **First-Time Successful Student Business Sellers vs Marketplace Sellers** | `orders`, `order_items`, `listings` (verified completed all-time) | Two distinct cohorts: (1) `firstTimeSuccessfulBusinessSellers` — earliest-ever verified completed `kind = 'business'` order falls in window; (2) `firstTimeSuccessfulSellers` — earliest-ever verified completed order of any kind falls in window | Earlier `pre_loved` sales NEVER disqualify a seller's first qualifying Student Business sale (verified live in Gate B `B5/B6/B7`) | `0` when no new sellers completed their first qualifying sale in window | Admin only |
| **Completed Donations & Units** | `free_notices` (`active`/`closed`), `free_notice_claims` | `COUNT` & `SUM(quantity)` where `claim.status = 'collected'` | Excludes merely posted, requested, reserved, expired, or cancelled claims; zero fabricated environmental estimates | N/A | Public aggregate, Admin |
| **Open Reports** | `reports` | `COUNT` where `status IN ('submitted', 'under_review')` | Uses hosted `reports` canonical initial status `'submitted'` | Excludes `'resolved'` and `'dismissed'` | Admin only |
| **Verified Rating** | `reviews` | `AVG(rating)` where `hidden = false` | Completed verified orders (**Verified Purchase**) or completed service requests (**Verified Service**) only | `null` ("No reviews yet") when `count === 0` — NEVER `5.0` | Public |
