# Buy-U Phases 7–9 — System Architecture, Migration Guide & Backlogs

## 1. Architectural Decisions (Hosted-Schema Aligned, P0.1–P0.12)
- **Hosted Schema Compatibility (P0.1):**
  - `free_notices` preserves hosted statuses (`active`, `closed`, `hidden`) and all hosted constraints (`already_placed = true`, `1–5 image_paths`, `spot_id NOT NULL`, `condition NOT NULL`, `title 5–100`, `description 10–2000`, `expires_at NOT NULL`). Incomplete drafts persist in separate private `public.free_notice_drafts` and publish atomically via `publish_free_notice_atomic`.
  - `reports` preserves hosted initial status `'submitted'` (`submitted | under_review | resolved | dismissed`), enforces an 8-reason whitelist + target existence + conversation-participant access in `submit_report_atomic`, and hides `admin_notes` from reporters via column-level `GRANT SELECT (...) ON public.reports TO authenticated`.
  - `profiles` maps admin user restriction/suspension cleanly to hosted `status = 'suspended'` (plus `restriction_reason` / `restricted_at`) without breaking `profiles_status_check`.
  - `listings` moderation sets hosted `status = 'hidden'` (NEVER `'removed'`), records `moderated_prev_status`, and protects admin-hidden listings via `trg_listings_guard_admin_hidden` so sellers cannot bypass moderation.
- **Services Marketplace (Phase 8A / P0.2):** Uses hosted `public.service_requests` with typed `preferred_date timestamptz`, request-level `mode IN ('remote','in_person')` validated against listing `service_mode`, preserved `'expired'` status, 48h `respond_by` expiry, and unique partial index `idx_service_requests_one_active_per_buyer_listing`. Excluded from paid sales and 2% commission; eligible for **Verified Service** reviews after buyer completion.
- **Free Items & Community Donations (Phase 8B / P0.6):** Reuses hosted `public.free_notices`, `public.donation_spots` (`Blok Alpha`, `Blok Beta`), and `messages.free_notice_id`, adding `public.free_notice_drafts` and `public.free_notice_claims` with `reservation_expires_at` (48h on accept), `expire_stale_free_claims_atomic` (never expiring `handed_over`), explicit inventory integrity exceptions (no silent `GREATEST(0, ...)`), and completed-only (`collected`) community impact tracking.
- **Direct Write Hardening (P0.4):** Direct `INSERT, UPDATE, DELETE` revoked from `PUBLIC, anon, authenticated` on `service_requests`, `reviews`, `free_notices`, `listing_views`, `notifications`, and `member_blocks` — all member mutations flow through validated `SECURITY DEFINER` RPCs. `trg_profiles_guard_system_fields` blocks client tampering with `profiles.last_active_at`.
- **Blocking & Privacy Enforcement (P0.5):** Private `internal_is_blocked_between(uuid, uuid)` backs DB `BEFORE INSERT` triggers on `conversations`, `messages` (preserving controlled active/disputed paid-order messages where `order_id IS NOT NULL`), and `offers`, plus service-request and free-claim RPCs. Hosted `is_member_blocked_between(uuid, uuid)` is hardened to reject unrelated third-party probing (`BLOCK_PROBE_DENIED`).
- **Verified Reviews & Public Storefront (Phases 8C/8D / P0.8 / P0.10):** Buyers submit and edit **Verified Purchase** reviews directly on `/orders` (`submit_verified_review_atomic`, `edit_verified_review_atomic`) and **Verified Service** reviews on `/requests`; sellers reply publicly on `/seller/analytics` and customize logo, banner, `business_info`, and `is_open` on `/seller/storefront` reflected on `/store/[sellerId]`.
- **Analytics, Notifications & Admin Audit Logs (Phases 8E–9F / P0.3 / P0.9 / P0.10):** Paginated analytics loader (`fetchAllPaginated`) feeds shared `src/lib/analytics/metrics.ts` (bounded `uniquePurchasers/uniqueViewers` conversion, strict `kind='business'` entrepreneurship cohorts, `firstTimeSuccessfulSellers`, proportional multi-item refund attribution, custom MYT date ranges, formula-safe CSV exports). `ListingViewTracker` records views on `/listings/[slug]`; header Bell shows live unread counts; `log_admin_audit_internal` returns `bigint` with nullable `uuid target_id` (text catalog refs stored in `details->>'target_ref'`).
