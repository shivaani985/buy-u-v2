# Buy-U Phases 7–9 — System Architecture, Migration Guide & Backlogs

## 1. Architectural Decisions (Hosted-Schema Aligned, P0.1–P0.18)
- **Hosted Schema Compatibility & Profile Security (P0.1 / P0.13):**
  - `profiles` preserves minimal column-level `UPDATE (display_name, faculty, bio, avatar_url, phone, updated_at)` grants; `guard_profile_system_fields_trigger` uses `SECURITY INVOKER` + `current_user IN ('postgres', 'service_role')` so trusted `SECURITY DEFINER` RPCs can update `last_active_at` & `notification_prefs` while direct client tampering fails with `42501`. Non-essential notification preferences persist strictly via `update_notification_preferences_atomic` + CHECK constraint (`inquiries`, `reviews`, `community` booleans), and `safe_insert_member_notification` is exception-safe.
  - `free_notices` preserves hosted statuses (`active`, `closed`, `hidden`), exact condition vocabulary (`New/Unused`, `Like New`, `Good`, `Fair`), and all hosted constraints; incomplete drafts persist in private `public.free_notice_drafts`, lock with `FOR UPDATE` on publish (`publish_free_notice_atomic`) to block concurrent duplicate publication, verify 1–5 distinct student-owned objects exist in `storage.objects` (`free-items`, hardened to 5 MB & JPEG/PNG/WebP), and allow donor edit/close via `manage_free_notice_atomic`.
  - `reports` preserves hosted initial status `'submitted'` (`submitted | under_review | resolved | dismissed`) and hides `admin_notes` via column-level `SELECT`; `reviews` hides `moderation_reason`, `moderated_by`, and `moderated_at` via column-level `SELECT` (P0.18).
  - `profiles` admin restriction maps to hosted `status = 'suspended'`, and `'restore'` strictly refuses to reactivate `'closed'` accounts (P0.16).
  - `listings` moderation sets hosted `status = 'hidden'` (NEVER `'removed'`), stores `moderated_by`, `moderated_at`, `moderation_reason`, `moderated_prev_status`, and protects all moderation columns on `INSERT OR UPDATE` via `SECURITY INVOKER` `trg_listings_guard_admin_hidden`.
- **Services Marketplace & Committed Expiry (Phase 8A / P0.2 / P0.14):** Uses hosted `public.service_requests` (`preferred_date timestamptz`, `mode IN ('remote','in_person')`, `'expired'`, 48h `respond_by`). Overdue `'requested'` rows persist `'expired'` cleanly via committed structured return in `update_service_request_status_atomic` (no rollback exception!) and standalone `expire_stale_service_requests_atomic` invoked by `scripts/phase7-9-expiry-worker.mjs`.
- **Free Items, Reservations & Expiry (Phase 8B / P0.6 / P0.15):** `update_free_notice_claim_atomic` revalidates `reservation_expires_at` AFTER locks before handover and commits `'expired'` + exact-once release without rolling back; already `handed_over` claims remain intact; `expire_stale_free_claims_atomic` is called independently (via worker & prior server round-trip) so failed claims never roll back expirations.
- **Direct Write Hardening & Phase 5 Compatibility (P0.4 / P0.18):** Direct `INSERT, UPDATE, DELETE` revoked from `PUBLIC, anon, authenticated` on `service_requests`, `reviews`, `free_notices`, `listing_views`, `notifications`, and `member_blocks`. Phase 5 `markConversationReadAction` is preserved via `mark_conversation_notifications_read_atomic`.
- **Blocking & Immutable Relationships (P0.5 / P0.16):** `BEFORE INSERT` & `BEFORE UPDATE` triggers on `conversations`, `messages`, and `offers` enforce bidirectional `internal_is_blocked_between`, block mutation of relationship columns, block `pending -> accepted` offer transitions when blocked (preserving cancel/decline & existing accepted/paid order fulfilment), and verify attached `order_id` participant ownership + authoritative verified payment for the active/disputed paid-order messaging exception.
- **Verified Reviews, Public Storefront & Analytics (Phases 8C–9F / P0.8 / P0.9 / P0.10 / P0.17):** Buyer **Verified Purchase** review/edit UI on `/orders`, **Verified Service** review UI on `/requests`, storefront banner/logo/info/open controls on `/seller/storefront` & `/store/[sellerId]`, `ListingViewTracker` on `/listings/[slug]`, live unread Bell badge, deterministically paginated analytics (`fetchAllPaginated`), unclamped pre-purchase viewer-cohort conversion (`N/A` when unattributable + separate `ordersPerViewer`), exact largest-remainder integer-sen proportional refund allocation (`allocateProportionalSen`), and distinct `firstTimeSuccessfulBusinessSellers` vs `firstTimeSuccessfulSellers`.
